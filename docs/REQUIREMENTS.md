# SIMerald 需求说明

SIMerald 的产品需求和设计决定。改动行为之前请先读一遍。

## 1. 一句话概述

**SIMerald** = 把 Komari 的 **Emerald 主题**改成一个 **SIM / eSIM 收藏展示站**。数据每天从站长的 Notion 数据库同步一次，界面尽量像素级保留 Emerald 的样子。

VPS 和 SIM 有很多相似之处：都要续费、都有价格和到期日、都来自世界各地。Emerald 里凡是能对应上的部分，都尽量用起来。

## 2. 设计决定

| #   | 决定     | 内容                                                                                                |
| --- | -------- | --------------------------------------------------------------------------------------------------- |
| 1   | 产品形态 | 独立产品，不依赖 Komari                                                                             |
| 2   | 起步方式 | fork [Komari Emerald](https://github.com/Tokinx/komari-theme-emerald)（MIT）修改，不从零重写        |
| 3   | 视觉要求 | 尽量像素级保留 Emerald 原样：布局、地球、卡片、动画、深色模式、配色、圆角。只改第 4、5 节列出的地方 |
| 4   | 公开范围 | 页面公开；号码只显示后 4 位；敏感字段只有登录后才显示（见第 6 节）                                  |
| 5   | 金额     | 公开：续费价格、折合月均 / 每年、余额、累计花费、剩余价值                                           |

| 7   | 主题设置 | 网页设置面板：登录后在页面里改，保存后马上生效（替代 Komari 后台的「主题设置」）                    |

| 9   | 同步     | 每天一次（默认 05:00，时区可设），另有「立即同步」按钮                                              |

## 3. 数据源：Notion

需要两个数据库，第三个可选：

| 数据库           | 作用                                                               |
| ---------------- | ------------------------------------------------------------------ |
| SIM 卡           | 每张卡一行，主表                                                   |
| 消费记录         | 首购、续费、充值的每一笔记录，通过关联字段指向 SIM 卡              |
| 扣款账户（可选） | 被上面两张表关联，只在登录后显示名称；读不到时跳过，不影响其他数据 |

- **只读**。SIMerald 绝不写 Notion。
- 用 Notion 官方 API（integration token，接口版本 2025-09-03，查询走 data source）。官方 API 能直接返回公式字段和汇总字段的计算结果，以 Notion 算出的结果为准。
- 数据库可以填 database ID、data source ID 或页面链接。
- 字段名不写死在代码里：放在字段映射配置里（默认值见 `server/mapping.ts`），别人接自己的 Notion 时在后台改映射即可。

### 3.1 计算规则（和 Notion 公式保持一致）

- **当前有效期至**：取消费记录里按「消费日期」最近的一笔「本次有效期延至」，同一天有多条取最晚的。
- **下次续费日期**：填了「下次续费日期（手动覆盖）」就用它（可能是日期范围），否则等于「当前有效期至」。
- **号码状态**：填了停用日期 = 已注销；过了当前有效期 = 已过期；其余 = 使用中。
- **剩余天数**：在浏览器端按「今天」实时计算，所以每天同步一次也不影响倒计时。
- **价格、月均、剩余价值**：沿用 Emerald `financeHelper` 的算法。price = 续费金额，currency = 续费币种，billing_cycle = 续费周期的天数（「不固定」当作没有周期）。
- **免费保号的卡**（续费金额 = 0）对应 Emerald 的「白嫖中」：不计入价值统计。
- **累计花费**：每张卡用 Notion 的「卡消费合计 CNY」；顶部的总数是所有卡相加（包括已注销的卡）。
- **汇率**：显示用 Emerald 自带的每日联网汇率；历史花费用消费记录里的「当时汇率」，也就是 Notion 已经算好的「等额 CNY」。

## 6. 隐私和安全

- **打码在后端做**。公开接口返回的数据里根本不能出现完整号码、管理账号、绑定的服务、扣款账户、数据检查、Notion 链接和记录标题；`server/view.ts` 用白名单挑选可公开的字段。
- 登录后通过同一个接口返回完整数据。
- 登录：一个站长账号，密码（scrypt 哈希）+ TOTP 两步验证 + 一次性恢复码；首次设置需要服务器上生成的一次性设置密钥，防止别人抢先设置。
- 「记住此设备 30 天」用 HttpOnly + Secure + SameSite=Strict 的 cookie。
- 连续输错暂时锁定（同一 IP 5 次锁 15 分钟，全站 15 分钟内 20 次也锁定）。
- 修改类请求必须带 `X-SIMerald-Request: 1` 请求头。
- Notion token、密码哈希、TOTP 密钥只放在数据目录或环境变量里，绝不进 Git 仓库；仓库里不放任何真实数据，截图只用演示数据。

## 7. 网页设置面板

登录后才能打开，设置项定义在 `shared/settings-schema.ts`，后端校验和前端表单都用它：

- **基础**：站点标题、默认视图模式、默认排序
- **公告**：启用、标题、内容（支持简单 Markdown）
- **页面**：头部展示模式、访客信息卡、未登录时隐藏后台入口、减弱过渡动画、已注销后置
- **备案**、**自定义背景**：照搬 Emerald
- 另外还有：数据同步（状态、立即同步、每日同步时间和时区）、Notion 连接（token 只写不读、数据库、字段映射）、账号安全（改密码、重新绑定两步验证、重新生成恢复码、退出其他设备）

## 8. 同步

- 每天一次，默认 05:00（Asia/Shanghai），可在设置里改；另有「立即同步」按钮。
- 同步结果存成本地缓存，页面只读缓存，不在访客访问时临时请求 Notion。
- 同步失败时保留上一次的数据，设置面板里显示失败原因；页面页脚显示「数据更新于 …」。
- 注意 Notion API 的速率限制（约每秒 3 次请求）和分页。

## 9. 不做的

- 续费提醒、Telegram 通知
- 写回 Notion
- CPU / 内存 / 硬盘 / 流量 / 速率 / 三网延迟这些 VPS 专属内容
- 多用户

## 10. 验收标准

- 和 Komari Emerald 并排打开，整体观感（地球、统计卡、卡片墙、列表、详情页、深色模式、手机端）一眼看去是同一套设计。
- 每张卡的国旗、类型、后 4 位、下次续费日期、剩余天数、价格、余额都和 Notion 一致。
- 未登录时，在浏览器开发者工具里查看所有接口响应，找不到完整号码、邮箱、绑定的服务、扣款账户。
- 登录必须同时通过密码和 TOTP；连续输错会被锁定。
- 设置面板改公告和头部模式，刷新后生效；「立即同步」能拉到 Notion 里刚改的数据。
- 没有 Notion token 时进入演示模式，页面正常显示示例数据。
- 仓库里搜不到任何 token、真实号码、邮箱。
